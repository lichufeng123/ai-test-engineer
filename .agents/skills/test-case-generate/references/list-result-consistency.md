# 列表结果完整性与一致性检查

适用于列表、搜索、筛选、分页，以及新增、编辑、导入、关联、取消关联、状态变更后由列表消费结果的功能。按需求和本轮授权选取场景，不把所有功能强制扩展到所有角色或平台。

## 对账前置

明确环境、角色与授权数据范围、组织、日期范围与时区、状态、搜索匹配规则、隐藏/软删除规则，以及允许的异步生效时间。不同条件的结果不能直接要求相等；连锁只能查询姓名时，不生成连锁手机号搜索用例。

使用受控fixture清单、已验证业务记录或全分页未筛选快照建立预期记录集合，再按已确认匹配规则推导查询预期。未筛选接口自身也可能漏数据，不能当唯一权威；UI与同一接口相等只证明渲染一致，不能证明业务正确。模糊搜索可能包含其他合法记录，需解释额外匹配，不能无条件要求全量集合与精确名称集合相等。

## 生成与审核清单

| 场景 | 具体断言与数据 |
|---|---|
| 搜索完整性 | 按已确认条件查询，应包含全部预期业务记录ID，并逐条核验匹配字段；既查漏记录，也查错误混入与重复。包含历史记录和新增记录，不能仅验证“查到一条”。 |
| 写入后的可查询性 | 新增、编辑搜索字段、导入、关联/取消关联、状态迁移后，按业务确认的新旧查询条件回读，确认正确纳入或排除；取消关联不一定删除接待，预期依需求。 |
| 筛选组合 | 单项和适用组合（日期、状态、员工、门店等）的交集符合规则；切换或重置条件后的集合、总数和页面条件一致。 |
| 分页完整性 | 收集所有页记录，页内与跨页无重复，合并集合不漏数据；总数、页大小与末页一致；翻页不丢条件，改变条件后的页码行为符合需求。数据覆盖页大小减1、等于页大小、加1及多页边界，缺真实第二页数据要阻塞，不能虚称通过。 |
| 排序与边界 | 依据已确认排序规则检查跨页顺序；同名不同ID、相同排序值、无匹配、日期首尾等适用边界。无稳定次级排序契约时，不编造固定并列顺序。 |
| 跨视图/角色一致性 | 同一授权组织、日期和状态下，对齐列表、详情、统计或已确认下游的记录身份与业务计数单位；连锁与门店只比较共享授权范围，不能比较双方全部数据。 |

每项标记用例ID及已覆盖、不适用（依据）或缺数据（具体缺口），交由既有语义审核流程复核。不同副作用、角色或失败机制保持独立用例，端到端用例不替代这些入口。

## 写入后搜索与筛选生效规则

通用设计规则：凡操作改变可搜索字段、筛选属性、关联对象或状态，在本轮适用范围内，不能只验证保存成功和无筛选列表回显；还须验证搜索、单项筛选及相关组合条件正确纳入或排除同一业务记录。此规则适用于新增、编辑、导入、关联、改派、取消关联和状态修改，具体匹配及状态语义以已审核需求为准。

生成规则时，将以下步骤写入适用的 `BF-*` 流程，并为显示一致性、查询纳入、旧条件排除及筛选组合分别生成可独立判定的 `A-*`：

1. 保存操作前的业务记录ID与搜索/筛选属性，记录本轮组织、角色和日期范围。
2. 执行修改后验证列表、详情的关键字段回显，并在适用的刷新或重新进入后确认持久化。
3. 用新名称、已确认的其他搜索字段及受影响筛选项查询，应查到同一记录ID；组合条件相符时纳入，不符时排除。每个独立搜索字段分别验证，不能用按ID能查到代替按名称能查到。
4. 用旧名称、旧关联对象或旧状态查询，核对同一记录是否按业务规则退出旧结果；保留别名/历史名称等功能有需求时按其规则判断，不能强制旧条件一律查不到。
5. 对比受控预期集合，检查不丢失、不重复、不误归属；刷新后重复受影响查询，遵守确认的异步窗口。

关联场景尤其要验证“关联对象ID/身份 → 名称等可查询业务属性 → 搜索/筛选命中”的完整关系。接口允许观察时核对关联后的身份和名称一致；列表可能通过联表或前端补全显示名称，不能据此推断搜索所需属性已正确保存或同步。验证业务可查询性，不强制特定数据库字段、冗余存储或索引实现。没有字段级证据的缺陷只能描述结果差异，根因需明确标记为研发/产品确认或待验证。

例如使用脱敏示例顾客A关联接待R：无筛选列表显示A后，仍须按A名称搜索并核对R的ID，再用适用员工、日期和关联状态筛选；若改关联为B，则按B可找到R，而按A是否仍包含R依已确认历史关联规则判定。数据不足只阻塞相应场景，不反复造数据或重试。

## 自动化与证据

按运行时数据计算预期ID集合，并比较缺失ID、额外ID、重复ID、条数及关键字段；不把本次偶然出现的7条或2条写成固定业务预期。列表超过一页时先完整翻页，不能将首页items直接与全量集合比较。写入后遵守已确认异步窗口；期间数据持续变化时需受控数据或快照，无法稳定对齐标待确认，不能直接报漏数据缺陷。

失败报告在缺陷章节直接附上查询条件和实际结果截图、同条件对照截图或业务数据证据，说明角色、组织、日期和快照时间；条数与记录ID差异另留回执，不能只附文件名或HTTP200。HTTP成功不等于业务结果正确。

执行中发现正式用例缺少对账步骤时，生成同一基线的可审核用例变更，绑定稳定用例ID与派生检查ID，不能将新增脚本断言冒充原正式用例已完整覆盖。
