# 权限测试设计规范

## 触发及范围

需求含权限开关、角色授权、组织数据范围、跨页面访问或操作鉴权时加载本规范。
只有浏览的功能不凭空增加编辑权限；有浏览和编辑的功能必须验证二者联动。
本文是测试方法，不是所有系统共用的权限业务规则。授权层级、继承关系、菜单隐藏方式、生效动作和操作限制从审核需求或项目适配器读取。

## 先隔离权限层，再改变开关

先列出：配置层、配置对象、被测角色、访问平台/视角、组织范围、功能动作、生效动作及来源。
不同配置层和访问视角分别建立稳定 context ID，不用一条“各角色均正常”覆盖全部。

- 测试角色权限时，上级功能资格和被测组织范围先开放，其余条件固定，只改变角色开关。
- 测试系统级资格时，保持下级角色权限具备，只改变系统级开关。
- 若存在上级限制，再单独测试上级未开放而下级已授权的联动，不能让它干扰角色测试。
- 可访问组织范围与功能权限分开：范围有/无 × 功能有/无四组，不凭功能权限越过组织边界。
- 同一账号在组织总体视角、切入下级组织视角、下级账号直接登录不是同一条用例。
- 权限保存后执行该项目确认的生效动作；重新登录生效的系统必须写出退出并重新登录，不能只刷新。

## 浏览与编辑组合

| 组合 | 核验 |
|---|---|
| 均无 | 菜单、页面、页面间跳转、直接地址及读写接口拒绝；拒绝写入后数据不变 |
| 仅浏览 | 列表和详情可读；字段只读、编辑入口不可用；修改接口拒绝且数据不变 |
| 仅编辑 | 按已确认契约验证自动带出浏览、拒绝配置或独立操作；契约未知则保留待决策，不自行选边 |
| 浏览及编辑 | 页面可读，编辑入口可用；保存后列表/详情回读一致 |

添加、删除、启停、导出等如果有独立权限，分别隔离验证，不把编辑权限解释成所有写操作。
只有浏览权限的多个子页面，覆盖全部开、全部关、各项单独开、各项单独关；不超过3个独立开关可穷举8组。
更多开关优先关键依赖与成对组合，记录未展开范围，不能声称穷举。

## 绕过及变化回归

- 有权页面上的跳转按钮、直接URL、收藏地址、前进后退不能绕过访问限制。
- 编辑撤权后按生效动作重新访问，验证只读及修改接口拒绝；浏览撤权也需验证编辑联动。
- 筛选、Tab、分页、刷新及组织切换后，入口、按钮、数据范围不丢失权限约束。
- 已打开编辑表单后撤权，生效后再次提交旧请求，验证服务端鉴权且数据不变。
- 撤权前先保存授权、执行生效动作并证明浏览/编辑成功，再撤权、再次执行生效动作并验证拒绝。不能把两次配置合为一步。
- 无浏览权限时，由独立有权控制账号回读拒绝前后快照；不能用读失败证明数据不变。撤权对照快照取初次成功编辑之后。
- 参数篡改、跨组织ID、列表/详情/统计/下游回读范围一致；UI隐藏不能代替接口验证。
- 状态或方案来源限制与权限是不同约束，有编辑权限也不代表可编辑所有状态/来源。
- 用两个可操作的同源对象隔离切换权限测试；被下发只读、对象不存在、目标功能未开放不能充当权限拒绝证据。目标先由有权账号证明请求可成功，再只改变被测账号的权限或范围。
- 每个步骤写明实际配置层、目标组织和被测账号；上级关闭场景不能写成在角色页面关闭上级资格。同一角色能否按不同组织配置功能开关，未确认时不自行假定。
- 依赖组合在保存处先分支：保存成功才执行生效动作验收新设置，拒绝保存则检查旧配置不变；未决口径不判缺陷。启停交叉用独立无冲突 fixture，先完成拒绝副作用判定，再执行其他成功操作。

## 机器设计检查

保存 `permission_matrix.json` 与唯一用例基线中的 `permission_test` 元数据。
矩阵 `contexts` 每项包含：`id/role/surface/grant_layer/source_ref/activation`；明确布尔字段
`supports_edit/upstream_gate/scope_required/surface_switch_required/filters_required`。
编辑功能还声明 `edit_only_policy=auto_grant_browse|reject_configuration|independent|deny_access|pending`。
存在独立操作时声明 `independent_operations`，使用 `add/delete/enable/disable` 等小写键；不存在则省略或为空数组。每项必须有正反向用例，不能凭编辑组合替代。
声明需要依赖权威来源，不能为了让门禁通过而编造。

用例的 `permission_test` 包含 `context_id/scenario/activation_performed/checks`。
场景：`granted/denied/revoked`；编辑功能增加 `browse_only/edit_only/browse_edit/revoke_edit/revoke_browse/stale_form`；
按矩阵增加 `upstream_disabled/scope_granted/scope_denied/scope_denied_no_permission/switch_context/filter_preservation`，可编辑且有筛选时再增加 `filter_readonly`。
范围与功能均无使用 `scope_denied_no_permission`；范围有、功能无使用固定已授权范围的 `denied`。
独立操作使用 `operation_<键>_granted/operation_<键>_denied`，分别检查入口和写后回读/拒绝且不变。仅撤浏览保留编辑用 `revoke_browse` 按依赖契约判断，不直接预设拒绝。
检查点：`menu/page/navigation/read_api/edit_control/write_api_no_change/save_readback/dependency_contract/scope`。
元数据必须对应真实步骤、逐步预期和证据计划；严禁只补标签。

```bash
ai-test permission-check \
  --matrix rules/permission_matrix.json \
  --cases cases/review-draft.json \
  --output runs/latest/permission_design_receipt.json
```

缺必需场景、读写鉴权、生效步骤则失败；编辑/浏览依赖未决则阻塞正式接收。
工具只检查已声明矩阵的设计覆盖，不证明矩阵已枚举所有角色、业务预期正确或真实测试通过。
独立语义复核必须检查配置层隔离、具体按钮/字段、逐步预期、来源和回读证据。
示范草稿可以展示假设，但不能凭检查通过成为正式业务规则或第二套正式用例基线。
