# Ego Lite 与 Playwright Web 回归执行速度实验

日期：2026-09-21

## 目的

评估 Ego Lite 是否能提升现有稳定 Web E2E 回归的执行速度。实验使用一个只读后台导航场景：复用已认证会话，从固定模块入口进入目标列表页，并同时断言组织身份、最终路由和页面标题。

内部地址、组织名称、账号、Cookie、Token 和业务数据均未写入本文。

## 同口径条件

- 相同认证状态，仅通过权限为 600 的临时 FIFO 在内存中传递。
- 相同 2560×1494 视口。
- 相同起始页面、点击路径和最终断言。
- 每个执行器采集 3 个正式样本。
- 全程只读，不执行新增、编辑、删除或提交。

## 结果

| 执行器 | 正式样本 | 通过率 | 稳态中位数 |
| --- | ---: | ---: | ---: |
| Ego Lite（执行器内部） | 3 | 100% | 595 ms |
| Ego Lite（含每轮 CLI） | 3 | 100% | 737 ms |
| Playwright（稳态热缓存） | 2 | 100% | 119.5 ms |

Playwright 首个新上下文样本为 3,189 ms，后续两个热缓存样本为 123 ms 和 116 ms。缓存状态对结果影响显著，因此首次上下文与稳态数据分别报告，不进行简单平均。

在稳定热回归口径下：

- Ego Lite 执行器内部耗时约为 Playwright 的 4.98 倍。
- 包含每轮 Ego Lite CLI 启动后，约为 Playwright 的 6.17 倍。
- 本实验没有观察到 Ego Lite 提升稳定脚本的执行速度。

## 稳定性观察

Ego Lite 第一次尝试使用文本 XPath 点击页签时定位失败。读取语义快照并改用页签 ref 后完成自愈，随后 3 个正式样本全部通过。Playwright 3 个匹配样本全部通过且无需定位修复。

这表明 Ego Lite 的语义快照适合页面探索、动态诊断和定位器修复，但探索、自愈和 CLI 调用会增加执行开销。已有稳定定位器时，Playwright 更适合高频批量回归。

## 结论与建议

1. 保持 Playwright 为稳定 E2E 和 CI 主执行器。
2. 将 Ego Lite 用于人工登录态复用、首次探索、失败现场复核和 Playwright 定位器修复。
3. 不使用“Ego 热会话耗时 ÷ Playwright 完整冷登录耗时”计算提速比例，因为起点不同。
4. 若要比较自动化开发效率，应另选尚未自动化的新用例，记录首次实现工时、人工介入次数、定位修复次数和后续维护工时；本实验只比较执行速度。
