# 环境与平台矩阵

项目通过 `ai-test.json` 声明环境，不在框架代码中写死地址。每个环境记录用途、发布顺序、账号角色、登录分支、平台可用性和数据限制。

## SIT 账号预检

正式进入页面前，从已审核账号/Fixture 索引按目标环境、所需角色和组织范围选定唯一非敏感账号别名，记在已有计划/章程中；先核对当前浏览器登录态，若身份匹配则复用，不能因为会话开启或历史曾成功就默认角色正确。账号为零或多候选时，在登录页前一次性向用户核实账号别名与适用角色/组织，不能索要密码。会话过期时优先用已配置的安全运行时凭据；确需用户输入时用经确认成功的浏览器 handoff，明确交还控制后再核验。SIT 测试授权不会因刷新或重新登录而失效；真正的工具/会话不可用仅阻塞受影响的 UI 步骤。

## 平台

| 平台 | 主要探索与验证 |
|---|---|
| Web | 页面、权限、请求、下载、响应式布局 |
| App | 容器登录、系统权限、返回、唤起、兼容性、性能 |
| H5 | 业务页面、接口、浏览器兼容；同时记录App容器差异 |
| 小程序 | 登录环境、微信授权、Minium业务链路、MiniTest云真机 |

当App提供H5时，应把两者关联到同一功能，但分别保存平台断言和证据。H5通过只证明H5业务面通过。

## 跨环境

首个测试环境完成探索、数据工厂和自动化建设。后续环境先校验版本、入口、角色和关键控件，只探索配置或部署差异。每个环境独立生成测试报告。
