# 系统与目标功能探索

## 接手具体功能时的第一步

按用户给出的功能名称及别名检索系统/功能地图、`assets/features/`、工作项和历史运行/缺陷记录。命中时列出已有入口、角色、业务对象、上次覆盖和未完成项，只复核本轮环境、版本、Fixture 与预期差异，再继续测试；不要把旧版的通过计入本轮。没有匹配记录时，标明查过的入口，做目标功能的增量探索，而不是默认全站重走。单次 UI 步骤无法控制时明确该步骤及工具错误，先完成不依赖它的历史梳理、测试数据与 Oracle 准备。

## 系统全局探索的触发

- 首次且无资产：提醒用户并执行。
- 用户手动要求：执行。
- 资产有效：跳过。
- 新环境、新平台、版本变化：增量探索。
- 资产失效：重建失效部分；基础身份、导航整体不可信时升级为全局探索。

## 系统探索清单

记录环境和版本、登录分支、完整菜单、角色权限、实体关系、跨端关系、瞬态弹窗、风险动作和常见恢复入口。菜单访问与业务理解分别打分，不把页面访问数量当作理解完成度。

瞬态弹窗资产应包含检测方式、处理动作、重试次数、恢复检查和失败证据。例如更新版本提示关闭后，需要确认仍停留在原业务页面。

## 功能探索清单

围绕角色、入口、实体、字段、状态、数据流、权限、缓存、异步、幂等、失败回滚、上下游和证据点探索。先做只读观察，再执行最小安全写操作。探索写入数据使用日期、环境、用例ID和唯一后缀命名。

## 成熟度

- L1：菜单和页面已定位。
- L2：系统角色、实体和主要数据范围已理解。
- L3：目标功能的断言、数据、证据和恢复方式已确定。
- L4：已跨环境验证并形成稳定自动化资产。
